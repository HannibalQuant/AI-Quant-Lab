# AI QUANT LAB — Edge Decay Response Playbook v1.0

**Document Class:** Constitutional Operational Playbook  
**Authority:** AI Quant Lab Monitoring, Risk, and Executive Governance  
**Status:** v1.0  
**Applies To:** Every monitored strategy, deployment, portfolio, breach, suspension, reactivation, retirement, and decay-related institutional action

## 1. Edge Decay Response Philosophy

Decay response protects capital and institutional knowledge by converting observed deterioration into evidence-bound, authority-bound action. Performance weakness is a symptom, not a diagnosis. The response must distinguish normal variance, data failure, implementation drift, regime mismatch, execution deterioration, portfolio interaction, and mechanism failure before changing the strategy or its authority.

## 2. Edge Decay Response Principles

No response without frozen evidence, trigger and severity classification, affected scope, candidate causes, authority, action class, follow-up, and audit. No silent continuation, limit override, retuning, implementation change, threshold change, reactivation, or false-alarm dismissal. Material breaches require review. Response is neither Validation, risk approval, nor deployment approval.

## 3. Edge Decay Response Identity Model

Every event receives immutable Edge Decay Response ID, record version, trigger identity, affected strategy/portfolio/deployment/monitoring versions, baseline version, evidence identity, owner, and opened time. Related recurrences link but do not overwrite prior events. Identity survives false alarm, rejection, resolution, retirement, and archive.

## 4. Edge Decay Response Object Model

The record shall define owner and responsible agent; strategy, portfolio, lifecycle, deployment, monitoring, DQS, IPS, VEP, RRP, EDP, MDRS, RCS, FFS, EDS, SFSS, XDS, WFRS, MCSTS, PSS and ODS identities; market scope and deployment/health states; trigger type/source/time/evidence/threshold, observed value, baseline/version, magnitude and severity; affected/unaffected scope; candidate/confirmed/rejected causes; required path, response, authority, owner/deadline, constraint changes, suspension/rollback/reactivation/retirement status, communications, limitations, contradictions, deviations, follow-up, institutional links, timestamps, and audit trail.

## 5. Edge Decay Response Lifecycle

**Proposed → Decay Signal Received → Trigger Classified → Evidence Frozen → Severity Assessed → Authority Identified → Response Selected → Action Authorized → Action Executed → Post-Action Monitoring → Return Path Opened → Revalidation Required → Reactivation Review → Retirement Review → Resolved → Rejected → Challenged → Archived**

Transitions record prior state, authority, exact scope, evidence, rationale, conditions, outputs, owner, deadline, and time. Non-applicable states may be bypassed only with recorded rationale; no authority gate may be skipped.

## 6. Decay Trigger Rules

Triggers include performance, expectancy, PF, risk-adjusted metric, win rate, trade/signal frequency, drawdown, tails, worst trade, loss clusters, regime, feature, parameter, execution, slippage, spread, costs, liquidity, capacity, DQS, IPS, monitoring, portfolio dependence, kill switch, governance, and unknown decay. Each binds threshold version, baseline, observation window, persistence, recurrence, uncertainty and source reliability.

## 7. Warning Response Rules

A warning states trigger, baseline, expected range, deviation, metric, scope, owner, enhanced monitoring, deadline, escalation threshold and prohibited interpretation. It may authorize watch or added observation only; it cannot authorize retuning, redeployment, scope expansion, or silent limit relaxation.

## 8. Degraded Response Rules

Degradation records evidence, severity, suspected cause, investigation, temporary capital/risk/deployment limits, monitoring cadence, return path, escalation condition, owner and deadline. Restricted authority remains explicit. Degraded operation is not normal operation and cannot persist without expiry and review.

## 9. Breach Response Rules

A breach record states threshold, magnitude, duration, recurrence, deployment scope, authority, immediate containment, communication, risk-control effect, suspension test, evidence package and next gate. Favorable aggregate performance cannot dismiss a material breach.

## 10. Suspension Response Rules

Suspension defines authority, exact strategy/portfolio/deployment scope, trigger evidence, safe state, open-position and capital treatment, monitoring, investigation, communications, reactivation and retirement criteria. Suspension executes promptly at the authorized severity and cannot self-expire.

## 11. Return-to-Research Rules

Return when market rationale, knowledge context, edge evidence, mechanism assumptions, alternative explanations or current market opportunity is inadequate. The order states research question, required artifacts/evidence, owner, scope, deadline and re-entry gate; live authority remains restricted or suspended.

## 12. Return-to-Architecture Rules

Return when hypothesis-to-mechanism mapping, modules, information needs, failure modes, regime logic or strategy-family expression no longer explains observed behavior. Architecture may not retrofit favorable rules into the old version; material redesign creates a new governed version or identity.

## 13. Return-to-Engineering Rules

Return when IPS drift, implementation defect, configuration divergence, state error, platform mismatch, control failure or architecture nonconformance is suspected. Engineering preserves the failed version, performs governed remediation and supplies renewed parity evidence before reuse.

## 14. Return-to-Experimentation Rules

Return when current evidence cannot discriminate causes, changed conditions are untested, sample is inadequate, controls failed, or remediation needs preregistered challenge. XDS precedes execution; no production retuning substitutes for an experiment.

## 15. Return-to-Validation Rules

Return when admissibility, reproducibility, robustness, leakage, overfitting, contradiction, limitation, or evidence scope may have changed. VEP independently determines supported scope; EDRP cannot self-revalidate.

## 16. Return-to-Risk Review Rules

Return when drawdown, tails, exposure, liquidity, capacity, execution, cost, portfolio interaction, operational control or monitoring assumptions change. RRP owns renewed risk acceptability and explicit limits; old limits do not automatically survive changed evidence.

## 17. Return-to-Executive Decision Rules

Return when continued authority, material downgrade, reactivation, changed capital, new scope, suspension release or retirement requires institutional decision. EDP cites updated VEP/RRP and unresolved issues; EDRP cannot issue Executive authority.

## 18. Deployment Rollback Rules

Rollback identifies source and target authorized states, exact versions, open-position handling, capital/exposure changes, controls, owner, incident evidence, verification, monitoring and communication. Rollback cannot silently activate an unapproved prior implementation or configuration.

## 19. Reactivation Rules

Reactivation requires confirmed root cause, remediation evidence, updated DQS and IPS, regime context, applicable VEP/RRP/EDP/DGS, monitoring readiness, exact limited scope, capital/risk bounds, kill conditions, expiry and review deadline. It is new authority, not restoration by elapsed time or recent profit.

## 20. Retirement Rules

Retirement records authority, reason, evidence, final strategy/deployment/portfolio state, open obligations, unresolved risks, consumer impact, learning artifact, archive and prohibited reuse. Renaming cannot revive retired logic without a new governed process.

## 21. False Alarm and Noise Rules

Dismissal requires frozen trigger, baseline adequacy, data and monitoring integrity, variance analysis, alternative causes, threshold fitness, confidence, independent challenge where material, and follow-up. False alarms remain evidence; repeated false alarms trigger baseline, threshold or monitoring design review rather than silent suppression.

## 22. Data Quality Decay Response Rules

DQS deterioration triggers affected-source quarantine, consumer identification, scope containment, alternate-source review, revision and lineage assessment, and separation of historical versus live impact. Strategy or edge blame is prohibited until data failure is bounded.

## 23. Implementation Parity Drift Response Rules

IPS drift triggers version/configuration lock, behavior comparison, mismatch classification, evidence impact, rollback or suspension test, and Engineering return. Implementation divergence cannot be labeled edge decay until reference behavior is restored or the difference is governed.

## 24. Regime Mismatch Response Rules

RCS mismatch identifies authorized, observed, transition, uncertain and alternative regimes; classification confidence; duration; strategy exposure; and whether the mechanism should be inactive, degraded or invalid. Regime mismatch is not automatically edge death, but deployment outside authorized regime is a scope breach.

## 25. Feature Drift Response Rules

FFS drift response assesses input DQS, distribution, missingness, transformation, stability, redundancy, interpretability, regime dependence and feature-to-mechanism relevance. Material drift may disable the feature-dependent scope and requires experiment/Validation before replacement.

## 26. Parameter Drift Response Rules

PSS drift includes unauthorized values/configuration, changing sensitivity, movement toward cliffs, island instability and state-dependent adaptation. Parameters are locked and evidence frozen; automatic reoptimization and post-decay neighborhood selection are prohibited.

## 27. Execution Deterioration Response Rules

Response assesses fills, rejects, cancels, latency, missed trades, order mapping, venue health, state recovery, IPS behavior and risk-control timing. It distinguishes executable degradation from strategy deterioration and may reduce capital, pause, reroute under existing authority, rollback or suspend.

## 28. Cost Deterioration Response Rules

Spread, fee, funding, borrow, rollover, impact and slippage increases are compared with EEP/RRP/DGS assumptions and net edge margin. Cost breach narrows or suspends affected scope and opens renewed experiment/risk review; gross performance cannot excuse negative executable expectancy.

## 29. Liquidity and Capacity Deterioration Response Rules

Response reviews depth, participation, exit capacity, simultaneous exits, crowding, venue concentration, impact, capital ceiling and stress. Scaling is frozen; exposure is reduced or suspended under authority when safe exit or controls cannot be supported.

## 30. Portfolio Interaction Decay Response Rules

PCS response evaluates correlation convergence, drawdown/tail dependence, exposure concentration, shared signals/features, regime crowding, liquidity competition, execution conflicts and simultaneous failure. Strategy-level health cannot dismiss portfolio-level breach; affected portfolio and components are explicitly scoped.

## 31. Edge Mechanism Failure Response Rules

Mechanism failure requires evidence that expected causal behavior, necessary conditions, controls, regime relationship or failure boundaries no longer hold. It triggers suspension or strict limitations plus return to EDS/research and independent Validation; parameter tuning cannot substitute for mechanism evidence.

## 32. Strategy Family Mismatch Response Rules

SFSS mismatch is assessed when observed behavior or failure resembles a different family, mechanism or regime dependency. The existing strategy cannot silently change family; return to architecture and new evidence are required for material reclassification.

## 33. Drawdown and Tail Breach Response Rules

Response records magnitude, duration, loss clustering, worst trade/period, realized versus expected tail, leverage, liquidity, portfolio interaction and risk limits. Hard or kill thresholds invoke immediate authorized containment; recovery after the breach does not erase it.

## 34. Monitoring Failure Response Rules

Missing coverage, stale metrics, alert failure, threshold/configuration mismatch, ownership gap or unavailable kill control reduces confidence in safe operation. Live authority is degraded or suspended according to severity until coverage, evidence and control readiness are restored.

## 35. Kill Switch Response Rules

Kill activation prioritizes safe containment within DGS/RRP/EDP scope and records trigger, authority, timestamp, affected orders/positions/capital, success/failure, communications and incident state. Override requires explicit higher authority and cannot erase the trigger. Failed kill behavior is critical and blocks reactivation.

## 36. Escalation and Authority Rules

Authority is mapped by action: Monitoring may warn/escalate; operational controls may execute pre-authorized limits/kill actions; Engineering may remediate but not reactivate; Validation determines evidence scope; Risk governs risk acceptability; Executive Decision governs advancement/reactivation/retirement; DGS governs operational readiness. Unclear authority defaults to containment and escalation.

## 37. Communication and Notification Rules

Notifications identify response/strategy/portfolio versions, trigger, severity, scope, current authority, action, owner, deadline, unresolved risks, evidence links and required acknowledgement. Critical events use governed escalation paths; absence of delivery is itself a monitoring breach.

## 38. Response Evidence Packaging

The frozen package includes response identity/version; affected records and exact versions; trigger/source/time/evidence/threshold/baseline/deviation; severity and confidence; affected/unaffected scope; candidate, confirmed and rejected causes; selected response, authority and action status; constraint changes, suspension/rollback/reactivation/retirement state; communications, post-action monitoring, limitations, contradictions, deviations, prohibited interpretations and follow-up.

## 39. Response Audit and Reconstruction

An independent reviewer must reconstruct what was detected, frozen, known, classified, authorized, communicated, changed, monitored and decided at every point without chat history or private memory. Audit preserves custody, artifacts, versions, timestamps, owners, transitions, rejected causes, overrides, challenges and outcomes.

## 40. Integration with MACP

MACP carries version-bound trigger, warning, breach, escalation, containment, suspension, return, reactivation, retirement, challenge and resolution messages. Scope, severity, evidence, authority, action, owner, deadline and acknowledgement are mandatory; messages do not replace records.

## 41. Integration with SMI

SMI stores current response state, affected versions, health, deployment authority, constraints, open causes, actions, owners, deadlines, blocks and evidence references. Conflicting or stale state blocks WOE progression and may trigger containment.

## 42. Integration with EES

EES governs provenance, admissibility, uncertainty, contradiction, freezing, chain of custody, challenge and consumer traceability. Trigger, adverse, false-alarm and remediation evidence remain linked throughout returns and reactivation.

## 43. Integration with WOE

WOE opens and routes response workflows, enforces owners, dependencies, authority gates, deadlines, returns, blocks, escalation, suspension, re-entry and archive. Stage skipping or unauthorized continuation is a governance breach.

## 44. Integration with Agent Registry

Only registered agents with explicit monitoring, emergency, research, engineering, Validation, risk, decision, evidence, message and workflow rights may take corresponding actions. Capability does not grant suspension override or reactivation authority.

## 45. Integration with Artifact Registry

ART registers triggers, frozen snapshots, investigations, cause records, limits, orders, rollbacks, returns, decisions, remediation, monitoring and learning artifacts with lineage, versions, owners, consumers, freeze, retention and supersession.

## 46. Integration with Strategy Lifecycle Standard

EDRP creates explicit SLS transitions to degraded, suspended, returned, revalidation, reactivation, retirement or archive states. No transition broadens scope or bypasses the canonical gates; material remediation creates new versions.

## 47. Integration with Autonomous Research Pipeline

ARP receives exact return stage, question, owner, required artifacts, re-entry criteria and retained live restrictions. Decay learning enters institutional knowledge; the pipeline cannot overwrite the incident or treat retuning as completion.

## 48. Integration with Data Quality Standard

DQS owns source identity, temporal integrity, defects, revisions, quarantine, remediation and eligibility. Data-related triggers retain downstream consumer impact and cannot be resolved by strategy changes alone.

## 49. Integration with Feature Factory Standard

FFS supplies feature identity, scope, lineage, stability, drift and failure modes. Feature replacement or transformation change requires versioning, IPS, experiment and applicable Validation before reliance.

## 50. Integration with Regime Classification Standard

RCS supplies current/historical regime evidence, confidence, uncertainty, transitions and contradictions. EDRP preserves authorized regime scope and routes uncertain or changed classifications without hindsight relabeling.

## 51. Integration with Edge Discovery Standard

EDS receives mechanism-failure evidence, alternative explanations, controls, costs and affected conditions. It may reopen edge discovery but cannot restore live authority.

## 52. Integration with Strategy Family Selection Standard

SFSS receives evidence of family mismatch, conditions, excluded regimes, failure modes and alternative families. Family change is a new governed selection and architecture handoff, not an incident patch.

## 53. Integration with Experiment Design Standard

XDS preregisters every decay investigation intended to create institutional evidence: hypotheses, nulls, data, metrics, controls, criteria, costs, deviations and interpretation limits. Incident-driven exploration is labeled exploratory.

## 54. Integration with Walk-Forward and Robustness Standard

WFRS tests whether decay is temporally clustered, persistent, window-dependent or consistent with expected degradation. New windows cannot be selected after outcomes to manufacture recovery.

## 55. Integration with Monte Carlo and Stress Testing Standard

MCSTS compares observed deterioration with governed path, cost, execution, liquidity, regime, tail and portfolio stresses. Scenario survival cannot reactivate a strategy; observed failures update evidence and risk review.

## 56. Integration with Parameter Stability Standard

PSS evaluates whether observed decay reflects drift from robust islands, cliff proximity, interaction instability or invalid parameter dependence. Retuning requires preregistration and fresh evidence, not production optimization.

## 57. Integration with Overfitting Defense Standard

ODS records incident-driven data access, threshold changes, candidate causes, parameter/feature variants and recovery selections. Repeated attempts to rescue performance consume degrees of freedom and may invalidate revalidation claims.

## 58. Integration with Implementation Parity Standard

IPS independently classifies reference-to-live differences across inputs, calculations, signals, orders, state, costs and controls. Critical or unknown mismatches block edge diagnosis and reactivation.

## 59. Integration with Portfolio Construction Standard

PCS supplies composition, exposures, dependencies, constraints, liquidity and portfolio health. EDRP distinguishes component decay from portfolio interaction and may suspend a portfolio without declaring every component dead.

## 60. Integration with Experiment Evidence Package

EEP packages governed follow-up experiments, controls, failures, deviations and reproducibility. It cites the incident and exact remediated versions; favorable post-incident runs cannot replace complete evidence.

## 61. Integration with Validation Evidence Package

VEP independently assesses updated evidence admissibility, robustness, reproducibility, leakage, overfitting, contradictions and scope. Validation may return, limit, reject or permit risk handoff; EDRP cannot alter its verdict.

## 62. Integration with Risk Review Package

RRP determines renewed acceptability, limits, monitoring, kill, suspension, reactivation and reassessment conditions. EDRP preserves existing limits until explicitly superseded and cannot accept residual risk.

## 63. Integration with Executive Decision Package

EDP owns continuation beyond conditional scope, material reactivation, changed live authority, return, rejection, suspension release and retirement decisions. It cites the complete response, VEP, RRP and unresolved issues.

## 64. Integration with Deployment Governance Standard

DGS executes authorized downgrade, pause, rollback, version lock, control verification, reactivation readiness and retirement closure. Any version mismatch, expired authority or failed kill/monitoring control blocks deployment.

## 65. Integration with Monitoring and Edge Decay Standard

MEDS is the primary governed trigger source and supplies baseline, thresholds, health states, incidents and monitoring evidence. EDRP returns response state, temporary limits, enhanced cadence, new triggers, suspension and post-action obligations; it cannot silently rewrite MEDS history.

## 66. Governance

Monitoring governance owns detection and initial triage; Risk Governance owns risk containment and acceptability; Executive Decision owns material continuation, reactivation and retirement authority; DGS executes operational state changes; independent Validation governs evidence scope. Changes require versioning, impact analysis, prospective approval and migration. Exceptions are scoped, owned, time-bounded, auditable and cannot waive evidence freezing, authority, critical containment, custody or reconstruction.

Mandatory response types include watch, limitations, enhanced monitoring, capital/risk reduction, constraint tightening, pause, paper/limited-live downgrade, rollback, strategy/portfolio suspension, every return path, reactivation review, retirement and invalidation. Severity is **INFORMATIONAL**, **WATCH**, **DEGRADED**, **MATERIAL BREACH**, **CRITICAL BREACH**, **SUSPENSION REQUIRED**, **RETIREMENT CANDIDATE**, or **INVALIDATING**; confidence is **HIGH**, **MEDIUM**, **LOW**, **INSUFFICIENT**, or **CONFLICTED**; maturity is **DETECTED**, **TRIAGED**, **ACTION_READY**, **ACTION_EXECUTED**, **MONITORING_ACTIVE**, **REVALIDATION_REQUIRED**, **REACTIVATION_CANDIDATE**, **RETIREMENT_CANDIDATE**, **RESOLVED**, **REJECTED**, or **SUPERSEDED**.

Every future AI Quant Lab decay, degradation, monitoring breach, kill event, suspension, rollback, return, reactivation or retirement action must conform to EDRP before institutional reliance. Resolution never erases the trigger, failed response, false alarm, authority path or learning.
